# IPTV Studio v1.1.0

本版完善线路检测、同频道择优和启停规则，并更新网页播放、操作说明及在线 Demo。

- 检测方式统一为快速、均衡、深度。均衡模式粗筛接续连续精测，复用已下载分片、解码和清单进度；受控双线路调度，同网关串行，不达标线路隔离复核。
- 连续精测增加多帧解码、PTS 与直播推进证据，区分明确不达标与未能验证。429、网络策略拦截及临时超时不会直接判为废源。
- 新配置默认每 8 小时更新、更新后检测，并同时要求速率严格大于 100 KB/s、画面高度至少 720 像素；已有设置保留。
- 四种检测入口统一启停规则：开启自动启停后，所测线路的有效首测恢复自动判定；同任务异常复测只更新记录，不改变启停。移除恢复自动按钮。
- 同样达标、流畅且无失败的线路优先画质和速率；保留失败、重连及卡顿降权。卡片首选速率、默认播放、线路列表与订阅导出共用排序。
- 精简播放器布局，修正手机端选择框自动获得焦点及关闭播放器后的焦点恢复；统一菜单解释和检测用词。
- README 补充部署、升级、默认配置与关键截图。在线 Demo 仅含虚构数据，改为只读浏览，避免模拟保存与实际服务逻辑混淆。

## 部署与升级

Docker Hub：`talktoo/iptv-studio:v1.1.0`，同步更新 `latest`。本次镜像平台为 **linux/amd64**。

下载运行 ZIP 和 SHA256SUMS，校验后解压，在目录内执行 `docker compose up -d`，打开 `http://服务器IP:8787`。发行包 Compose 固定版本；仓库 Compose 使用 latest。容器内为 `PORT=8787`，不支持 `mport`。

升级前停止原服务并备份整个数据目录，继续挂载原 `./data:/app/data`。之前使用 8788 外部端口的用户可保留 `8788:8787`；本版示例改为 `8787:8787`。不要同时启动两个实例访问同一数据库。

运行包与 Docker 构建采用文件白名单，保留运行模块、HLS.js 和许可文件；不包含数据库、家庭订阅、日志、缓存、测试、截图或研究材料。镜像包含 Python、Node 和 FFmpeg，应用以非 root 用户运行。

## 验证与结论范围

发布流程先运行全部隔离回归，再构建镜像，验证空库启动、默认设置、订阅输出、播放资源、FFmpeg、非 root 进程、重启数据保留和镜像文件白名单，通过后才发布。

真实线路受上游和网络变化影响；通过数量或模拟回归不能证明准确率提升，也不保证所有场景提速。在线 Demo 使用模拟结果，不能播放真实频道。
