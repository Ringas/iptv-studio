# 频谱 IPTV Studio v1.1.1

本版在已有线路检测与择优基础上，重点完善面向普通用户的运行日志和排错信息。新版本验证完成后替换并清理 v1.1.0 发布及对应镜像标签。

## 本次更新

- 默认用简短中文说明更新、检测和播放的关键结果。正常线路一条结果；异常时说明原因、复测等待与保留状态，轮询和逐片信息默认不刷屏。
- 多线路日志带频道、线路编号和来源；诊断模式可关联任务、线路与播放会话，保留阶段耗时、解码证据、缓冲估算和组件退出原因。
- 敏感 URL 路径、查询参数、用户名、密码和请求凭证自动遮蔽；重复播放异常限频，后台更新计划故障恢复后给出提示。
- 默认运行时区为上海（Asia/Shanghai）。普通日志形如 `2026-11-17 16:30:25.123 +08:00`；JSON 时间字段使用带偏移的 ISO 格式，历史检测时间不改写。
- 继续提供快速、均衡、深度三种检测方式。均衡检测复用粗筛下载与解码结果，受控双线路调度，同网关串行；不达标线路隔离复核。
- 首选速率、默认播放、线路列表和订阅导出共用排序。同样达标、流畅且无失败时优先画质和速率；保留失败、重连和卡顿降权。
- 保留四入口一致的启停规则：开启自动启停后，有效首测恢复自动；同任务异常复测不覆盖启停。429、超时和网络拦截仍属于未能验证，不直接判废源。
- 清理临时发布流程和未使用字段；发行包与镜像继续使用运行文件白名单，并保留必要组件和许可文件。Docker Hub 中文说明同步来自 README，避免多份说明过时。

## 部署与升级

镜像：`talktoo/iptv-studio:v1.1.1`，同步更新 `latest`，平台为 **linux/amd64**。

下载运行 ZIP 与 SHA256SUMS，校验后解压，运行 `docker compose up -d`，打开 `http://服务器IP:8787`。发行包 Compose 固定版本，仓库 Compose 跟随 latest。

升级前正常停止旧服务并备份整个数据目录，继续挂载 `./data:/app/data`。容器内部端口为 8787；原来使用 `8788:8787` 的用户可保留该映射。不要同时启动两个实例访问同一数据库。

默认日志为中文摘要。持续遇到问题时设置 `IPTV_LOG_LEVEL=DEBUG`；需要结构化诊断时另设 `IPTV_LOG_FORMAT=json`，详见 [运行日志与排错](https://github.com/Ringas/iptv-studio/blob/main/docs/logging.md)。

## 验证范围

发布前执行全部隔离回归、镜像空库启动、默认门槛、上海时区、订阅输出、播放资源、FFmpeg、非 root 应用进程、重启数据保留和运行文件白名单检查。

真实线路可用性受网络和上游变化影响，模拟回归与通过数量不能证明准确率提升，也不保证所有场景提速。在线 Demo 仅使用虚构频道和模拟检测结果。
