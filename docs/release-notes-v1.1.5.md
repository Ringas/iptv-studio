# 频谱 IPTV Studio v1.1.5

允许在检测过程中管理订阅：信息立即保存，内容更新排队执行；同时完善台标订阅、缓存与试播恢复，并对正式镜像采用经过逐层验证的 gzip 高压缩。

## 订阅与任务

- 检测或更新运行时，可以新增、编辑、停用和删除订阅；重复保存同一源只更新最终地址，队列重启后保留。
- 名称、优先级和周期修改不打断有效检测。地址、类型或启停变化后，旧更新和旧检测结果不能回写失效内容。
- 手动保存和单源刷新不触发线路检测，原有自动启停与同任务异常复测规则保持一致。

## 台标与试播

- 支持 JSON 台标订阅，以及关闭、浅色、深色、透明四种台标优化；手动台标优先，未匹配时由原订阅兜底，保存后独立处理。
- 按内容去重缓存，每周核验，内容未变复用已有图片；未引用台标清理，失败保留可用缓存。检测中批量优化让出资源，前台显示独立进度。
- 完善上游错误透传、冷却识别与有限播放恢复。429、超时、网络拦截继续保留为未能验证，不降低线路检测门槛。

## 清理、瘦身与压缩

- 清理未使用导入和重复入队 SQL，合并订阅页队列查询；不新增应用运行依赖。
- 延续精简运行环境与显式运行文件白名单，保留必要 Python、Node.js、FFmpeg、证书、时区及许可；发布包不含本地数据库、配置、凭证、缓存、测试媒体或研究材料。
- 使用独立构建的默认 gzip 与 gzip9 镜像进行对照，逐层验证解压后摘要和运行配置完全一致。压缩报告 `COMPRESSION.json` 随 Release 提供，本次压缩层合计由 88,307,685 降至 88,106,218 字节，节省 201,467 字节（0.228%）；现有镜像已较精简，压缩收益有限。
- 压缩镜像完整回归通过后才发布；上传已验证的同一份 OCI 镜像，推送和同步 latest 时不重新压缩，并拉取复核。压缩减小下载及存储传输量，不代表解压后的文件体积或播放速度同幅改善。

## 升级

镜像为 `talktoo/iptv-studio:v1.1.5` 与 `latest`，平台 linux/amd64；旧版本保留。升级前备份原数据目录，沿用原挂载与端口。默认上海时区，只有需要其他时区时才设置 TZ。

```sh
docker compose pull
docker compose up -d
```

在线 Demo 仅使用虚构数据。验证范围为现有隔离回归、队列并发场景和压缩完整性，不宣称所有真实线路性能或准确率提升。
