# 开发与验证

[返回项目首页](../README.md)

## 开发原则

- 以 `main` 为开发基础；功能、配置与用户操作见项目首页和[使用说明](usage.md)，不以历史报告替代当前实现。
- 修改前检查仓库状态，保留未提交改动。测试、预览和真实线路对照使用独立数据目录与端口，不覆盖正式数据库。
- 家庭订阅、真实媒体地址、凭证、数据库、日志和缓存留在本地，不进入 Git、演示数据或发布产物。
- 提交、版本更新及发布说明使用中文。GitHub 源码推送不代表 Release、Demo 或镜像已同步发布。

## 业务约束

- 订阅更新保留频道整理规则、检测记录和手动启停。旧订阅版本的下载与检测结果不能回写已变更或删除的源。
- 自动启停、同任务异常复测、当前门槛与历史结论的规则见[使用说明](usage.md#检测与启停)；不要用硬写检测结果修正判定。
- 首选播放和订阅导出使用标准排序；页面展示顺序独立维护，不应改变播放、发布资格或导出结果。
- 台标处理独立于线路检测，保留缓存复用、失败兜底与检测优先；修改运行文件时同步核对构建白名单。

## 验证入口

需要 Python 3.10+、Node.js 22+ 和 FFmpeg。在仓库根目录执行：

```bash
python3 scripts/verify_release.py
```

统一入口执行语法检查与根目录隔离回归；`verify_route_consistency.cjs` 由 Python 测试提供快照，不单独执行。新增测试应使用临时库、本机模拟源或受控响应。

真实线路结论需固定订阅快照和样本、交替测试版本，并记录耗时、逐条结果、所有重试和失败原因；分歧额外复核。网络拦截、限流或临时超时不当作废源，不能从通过数量推断准确率或性能提升。

## 运行环境与发布

- `.dockerignore` 与 `scripts/package_release.py` 控制运行文件，保留必要组件、证书、时区和许可，排除私人数据及开发生成物。
- `runtime-prune.py` 检查 ELF 传递依赖，并保留动态加载模块。升级基础镜像、Python、Node.js 或 FFmpeg 后，重新验证依赖、容器内回归、试播、HTTPS、时区和持久化。
- 正式发布应使用已验证的同一份镜像产物，核对压缩前后的原始层与运行配置；代码或构建输入改变后不能复用旧验证结论。
- 发布流程及候选验证记录见 `.github/workflows/` 与 `.github/release-validation.json`；历史发行与维护记录保留在对应文档和 Git 历史，不作为运行依赖。
