# 运行日志与排错

运行时区默认 `Asia/Shanghai`（UTC+08:00），Python 与检测子进程沿用同一时区。普通日志时间形如 `2026-11-17 16:30:25.123 +08:00`；JSON 的 `time` 字段形如 `2026-11-17T16:30:25.123+08:00`。数据库继续保存 Unix 时间与原有 UTC 检测时间，不改写历史记录。

默认日志面向日常使用，直接出现在终端或 `docker logs` 中：更新与检测有开始、结果和总耗时；正常线路一条结果，异常线路说明原因和复测等待；网页播放有开始、必要异常和关闭摘要。后台轮询、健康检查和每个媒体分片不会在默认级别逐条输出。

以下仅为虚构示例：

```text
[时间] [信息] 开始线路检测
[时间] [信息] 准备线路检测 ｜ 共 8 条线路
[时间] [信息] 演示综合 · 示例订阅 ｜ 首测 ｜ 通过 ｜ 直连可播 · 流畅 · 2.50 MB/s · 1920 × 1080
[时间] [提醒] 演示新闻 ｜ 限流冷却后复测一次 ｜ 原因：上游返回 HTTP 429 ｜ 等待 8 秒
[时间] [提醒] 演示新闻 · 示例订阅 ｜ 异常复测 ｜ 未能验证 ｜ 保留原检测及启停状态 ｜ 原因：连接暂时超时
[时间] [信息] 检测完成 · 7 条通过 · 0 条未通过 · 1 条待确认 ｜ 耗时 86.2 秒
```

## 遇到问题先看什么

| 日志提示 | 含义与处理 |
| --- | --- |
| 更新失败，保留旧快照 | 新订阅未成功取得或解析；检查地址、网络与授权。原频道数据继续保留 |
| 上游限流，等待后复测 | 服务器要求降低请求频率。不要连续点检测；等待冷却后再试 |
| 未能验证、超时或网络策略限制 | 本次证据不足，不代表线路永久不可用；在可访问上游的网络中稍后复核 |
| 速率或画面高度未达标 | 对照设置中的通过门槛；历史检测结果与当前门槛是两回事 |
| 检测组件异常退出 | 查看同一时刻的诊断日志，检查 Node、FFmpeg 是否可执行；不直接判为废源 |
| 播放传输失败 | 上游、格式或媒体传输发生异常；可等待播放器重试或切换线路，试播不会改启停 |
| 媒体请求多、完整传输少 | 可能是切台提前取消，也可能是上游中断；结合是否有传输失败提示判断，不能仅按计数认定坏源 |
| 更新计划暂时无法执行 | 检查数据目录权限和剩余空间；后台会继续尝试，恢复时输出提示 |

## 按需开启诊断

持续出现问题时，在 Compose 的 `environment` 中添加以下配置并重建容器；数据挂载仍沿用原目录：

```yaml
environment:
  PORT: "8787"
  TZ: Asia/Shanghai
  IPTV_LOG_LEVEL: DEBUG
  IPTV_LOG_FORMAT: text
```

默认 `IPTV_LOG_LEVEL=INFO`。`DEBUG` 才输出检测阶段变化、逐片读取/解码与缓冲诊断、网关会话、检测组件退出信息和访问请求。不是每秒重复打印相同阶段。

需要交给开发者分析时，可设置 `IPTV_LOG_FORMAT=json`。每条事件为一行 JSON，包含任务标识 `task_id`、稳定线路标识 `route_id`、播放标识 `play_id` 或请求标识 `request_id`。这些标识可把并行任务、首测和复测关联起来；默认中文输出不展示这些内部字段。

诊断日志保留 HTTP 状态、错误分类、解码帧数、PTS 推进证据和测量数据；发生后台异常时记录异常类型及文件/行号。Node 的错误输出和 FFmpeg 解码失败尾部也可用于定位，不再直接丢弃。

URL 的路径、查询参数、用户名和密码会隐藏，Cookie、Authorization 等敏感字段会遮蔽；不记录请求正文或原始请求头。线路可用频道名、来源及稳定标识对照；显示的线路编号按本次任务取得的目录排序，后续检测可能使目录重新排序。诊断仍可能包含频道名称与上游主机，分享前请检查。

日志写入容器标准输出，不在容器里另建无限增长的日志文件。网页「任务记录」继续保留每类最近 250 条；Docker 日志保留范围由宿主机日志驱动管理，例如：

```yaml
logging:
  driver: json-file
  options:
    max-size: "10m"
    max-file: "3"
```

## 借鉴依据

参考 [akiralereal/iptv 的请求与分片统计](https://github.com/akiralereal/iptv/blob/main/app.js) 和[统一时间戳输出](https://github.com/akiralereal/iptv/blob/main/utils/colorOut.js)：记录业务路径、结果、回退与耗时，汇总重复事件。本项目侧重线路管理与检测，因此增加任务/线路关联、未能验证的原因和启停决策诊断；没有移植对方的抓取模块或日志依赖。
