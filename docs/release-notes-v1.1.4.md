# 频谱 IPTV Studio v1.1.4

将经过功能及检测对照验证的精简运行环境作为正式开发主线，减少镜像中不参与运行的内容，保留现有功能与检测标准。

## 更新内容

- `main` 采用精简实现；瘦身前主线保存在 [history/pre-slim-v1.1.3](https://github.com/Ringas/iptv-studio/tree/history/pre-slim-v1.1.3)，对应提交 `329df81`。旧版本 Release、版本镜像和测试镜像保留。
- 构建时检查保留 ELF 程序、扩展和插件的传递依赖。缺少依赖时在删除前中止；保留 NSS、OpenSSL、Python 必要动态模块、CA 证书、时区及许可文件。
- 实际裁剪 50 个未被保留组件依赖的共享库文件及 38 个别名链接、15 个 Python 自测扩展、原来已缺少配套包的 `_tkinter` 扩展，以及 2 个 Python `pkg-config` 文件；移除少量非必要文档链接，保留许可原文件。
- 清理未使用的 `urlopen` 导入、无调用的 `stateBadge` 界面函数及其专属样式。不调整检测算法、通过门槛、启停、排序、订阅导出、播放器缓冲或重试规则。
- 固定 Node/Python 基础镜像为对照验证时的摘要。裁剪脚本仅用于构建，不进入最终镜像的应用目录；运行 ZIP 保留此脚本以支持自行构建。
- 对照构建的镜像体积约由 **96.31 MB 减至 88.51 MB，减少 8.1%**；未压缩文件减少约 18.20 MB。体积为对应构建的统计，不代表检测或播放速度提升。

## 对照验证

对比 `talktoo/iptv-studio:v1.1.3` 与 `talktoo/iptv-studio:slim-test-55f8cf7`：

- 两版使用各自镜像内的实际业务文件，分别通过 **41 项完整隔离回归**。
- **17 组**频道状态、手动启停、门槛边界及 M3U/TXT/JSON 导出快照完全一致。
- 同一运行环境交替执行 **33 组、66 次实际探测**，覆盖三种检测模式、720p/1080p 正例、480p、损坏分片、清单不推进、低速、429、网络拦截、超时，以及实际 DNS/TLS 连接；达标结论、错误分类、分辨率、解码帧数、时间戳推进、重试等待等字段无分歧。
- 可完整下载解码的低速样本，两版测得约 **53.6 KB/s**，三种模式均判为速率未达标。429、网络策略拦截及超时均保持未能验证，不判作废源。
- 逐文件哈希对照确认保留的运行组件内容相同，改动文件只有上述三处业务代码清理；构建后继续检查镜像启动、解码、证书、时区、非 root 应用进程及重启持久化。

## 部署与升级

镜像：`talktoo/iptv-studio:v1.1.4`，验证通过后同步更新 `latest`；平台 **linux/amd64**。Compose、端口和原数据卷继续沿用，默认上海时区，无需额外设置 `TZ`。

```bash
docker compose pull
docker compose up -d
```

升级前停止服务并备份整个数据目录，继续使用原数据挂载。发行 ZIP 仅包含必要运行源码、构建文件、固定版本 Compose 及许可，并提供 SHA256SUMS；不包含本地配置、数据库、家庭订阅、凭证、日志、测试媒体或临时诊断材料。

在线 Demo 同步主线界面，仅使用虚构数据，不连接真实直播源。
